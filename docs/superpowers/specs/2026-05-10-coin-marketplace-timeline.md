## 三、关键风险 & 影响时间的因素

### 风险 1：支付通道对接（最大变数）

| 支付方式 | 对接难度 | 预计耗时 | 风险 |
|---------|:-------:|:--------:|:----:|
| 微信支付 | ⭐⭐⭐ | 1周 | 需中国大陆企业资质 |
| 支付宝 | ⭐⭐ | 0.5周 | 相对简单 |
| Stripe（信用卡） | ⭐⭐ | 1周 | 文档好、API 现代 |
| PayPal | ⭐⭐ | 0.5周 | 文档好 |
| PayNow（新加坡） | ⭐⭐⭐⭐ | 1~2周 | 需新加坡本地银行合作 |
| GrabPay（马来西亚） | ⭐⭐⭐⭐ | 1~2周 | 需马来西亚本地商户资质 |
| FPX（马来西亚） | ⭐⭐⭐⭐⭐ | 1~2周 | 最复杂的本地支付 |

> **建议**：用 **Stripe** 统一对接可快速覆盖信用卡 + GrabPay + FPX（Stripe 在东南亚支持这些），大幅减少对接时间。只需 Stripe + 微信 + 支付宝 + PayNow 四个直连即可。

### 风险 2：多语言

- 4 国语言需要 UI 文案全部翻译
- 后端的错误消息、邮件模版、通知也需多语言
- 建议使用专业的翻译服务，避免 Google 翻译质量
- 预计翻译+验证需要额外 1~2 周（可在开发中并行）

### 风险 3：第三方评级公司 API

| 评级公司 | API 情况 | 对接难度 |
|---------|---------|:--------:|
| NGC | 有公开 API/数据库 | ⭐⭐ |
| PCGS | 有公开 API/数据库 | ⭐⭐ |
| PMG | 同 NGC 集团 | ⭐⭐ |

> 这三家都有评级编号查询接口，技术难度不大。

### 风险 4：合规要求

| 地区 | 要求 | 影响 |
|------|------|:----:|
| 新加坡 | PDPA 数据保护法 | 隐私政策、用户数据管理需合规 |
| 欧洲 | GDPR（若用户涉及） | 数据删除权、数据可移植性 |
| 马来西亚 | 个人数据保护法 | 类似 PDPA |
| 中国 | 《个人信息保护法》 | 需注意数据出境问题（如果服务器在新加坡） |

> 合规成本主要在文档和隐私策略调整上，不直接影响开发时间。

## 五、建议

| 如果想 | 建议 |
|--------|------|
| **最快上线** | 用方案 C（5人团队），3个月完成。多出的人员工资 vs 提前1个月上线，自己权衡 |
| **性价比最高** | 方案 B（3人团队），4个月。适合大多数创业项目 |
| **预算紧张** | 方案 A（2人团队），5.5个月。但注意后端单人压力大，可能会延期 |
| **进一步压缩时间** | MVP 策略：先上线核心功能（仅 Stripe+微信+支付宝 3种支付，其他慢慢加） |

> **MVP 最低可行版本（可按此先上线再迭代）：**
> - 支付：仅 Stripe（信用卡）+ 微信支付（3种 → 缩短 3 周）
> - 商品：支持评级编号展示但先不做 API 实时查询（缩短 1 周）
> - 多语言：先上英文+简体中文，后续再补充繁中+日文（缩短 2 周）
> - **MVP 总工期可压缩至 8~10 周（2.5 个月）**
